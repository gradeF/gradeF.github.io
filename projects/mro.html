1

데이터 중심(Data-Driven) 인벤토리 시스템 설계 및 구현

개발 의도. 기획자가 CSV 파일 수정만으로 프로그램 내 아이템 데이터를 실시간으로 수정할 수 있는, 확장성 높고 독립적인 인벤토리 아키텍처를 구축했습니다.

Data Flow
flowchart LR
  A[CSV 파일] --> B[CSV Parser]
  B --> C[Data Manager]
  C --> D[인벤토리 시스템]
  D --> E[Unity UI]
  D --> F["3D 프리팹 동적 시각화"]
  • Model — CSVParser / CSVManager / CSVReader / Data Struct: 고유 ID를 Key로 Dictionary 캐싱
  • Controller — InventoryItem(슬롯 아이템 객체) / InventoryController(상태·데이터 흐름 총괄)
  • View — 타 개발자의 비동기 스크롤 UI 컴포넌트에 MVC 기반 데이터 바인딩 로직을 결합 (스크롤 UI 구조는 수정 불가 조건)
신규 데이터 클래스 정의만으로 자동 바인딩되는 확장성을 확보해, 인벤토리 UI를 완전히 갈아엎어도 코드 수정 없이 대응 가능한 독립적 컴포넌트 구조를 만들었습니다.
2

확장성을 고려한 CSV 데이터 로드 파이프라인 구축

개발 의도. 기획 데이터를 코드와 완전히 격리해 개발자 개입 없이 기획자가 독립적으로 콘텐츠를 추가·제어할 수 있는 공용 파이프라인을 만들었습니다. 협업 효율을 위해 저수준 파일 처리와 고수준 파싱/캐싱 레이어를 나눠 공동 개발했습니다.

  • FileStreamReader — 로컬 디스크 CSV를 안전하게 읽는 저수준 I/O 클래스
  • CSVParserBase<T> — 제네릭 구조로 다양한 데이터 클래스에 자동 매핑하는 공용 파서
  • MasterDataManager — 유일성이 보장된 Dictionary로 메모리 상주, 다른 시스템의 안전한 접근을 중재
인터페이스 규격을 먼저 정의하고 개발해, 파일 읽기 방식이 바뀌어도 파서 엔진과 인벤토리 시스템은 사이드 이펙트 없이 독립 동작합니다. 기획자의 오타·타입 실수로 인한 런타임 크래시를 막기 위해 예외 처리를 결합하고, 로그 시스템과 연계해 오류가 발생한 정확한 라인(Line)을 추적할 수 있게 했습니다.
3

사용자 환경 설정(Preference) 관리 시스템 및 UI

개발 의도. 사용자가 변경한 환경 설정을 유지·관리하기 위해 섹션별 관리가 쉽고 직관적인 편집이 가능한 .ini 포맷을 선택했습니다. 싱글톤 사용을 의도적으로 지양해 결합도를 낮췄습니다.

  • .ini 파서 → 데이터 저장 클래스 → 접근/제어 중재 클래스 → Controller → Viewer의 5단계 레이어 파이프라인
  • 런타임에는 인메모리 값만 변경하고, 옵션 창을 닫거나 저장 버튼을 누를 때만 파일 작성 — 배치 쓰기로 디스크 I/O 최적화
  • Controller의 데이터 상태 변경을 Viewer가 감지해 자동 동기화하는 Observer 구조로 UI와 로직을 완전히 분리
