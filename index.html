복잡한 실시간 시스템을 안정적인 구조로 풀어냅니다

2017년 VR 게임 NIGHTMARE부터 2025년 NVIDIA Omniverse 기반 웹 스트리밍 POC까지, VR·AR·메타버스 콘텐츠와 실시간 협업/스트리밍 시스템을 꾸준히 개발해왔습니다.

싱글톤 남용으로 인한 결합도 문제, WebRTC 빌드 아키텍처 불일치 같은 실제 트러블슈팅 경험을 통해 이벤트/옵저버 기반 구조와 레이어 분리 설계의 중요성을 체득했고, 이를 여러 프로젝트에서 반복 적용하며 유지보수 가능한 코드를 만드는 것을 최우선 가치로 두고 있습니다.

Web–Omniverse 실시간 스트리밍 시스템 구축

개발 의도. 고사양 GPU 없이도 브라우저만으로 Omniverse 3D 씬에 접근해 실시간으로 협업할 수 있는 환경이 필요했습니다. 별도 클라이언트 설치나 3D 뷰어 없이, 웹 브라우저에서 Omniverse Kit 앱을 원격 스트리밍 받아 조작하는 하드웨어 제약 없는 협업 리뷰 워크플로우를 검증했습니다.

  • NVIDIA web-viewer-sample 기반으로 Kit 앱(서버) ↔ WebRTC ↔ 자체 제작 웹 클라이언트 구조 구축
  • 웹 클라이언트는 React + TypeScript + Vite로 UI/UX를 새로 제작 (샘플은 구조만 참고)
  • JSON 기반 커스텀 메시지 프로토콜(event_type + payload)을 확장해 씬 로드 요청, 오브젝트 선택 동기화 등 양방향 이벤트 처리 구현

OpenUSD 기반 데이터 파이프라인 개발

개발 의도. FBX/OBJ 등 외부에서 제작된 3D 에셋을 Omniverse에서 바로 활용하려면 OpenUSD 포맷 변환이 필요합니다. 수작업 변환 없이 일관된 파이프라인으로 USD Stage에 편입시켜 곧바로 협업/스트리밍 시스템에서 사용할 수 있도록 했습니다.

  • AssetImporter — 외부 포맷 파일 로드 및 파싱 진입점
  • USDConverter — 지오메트리·머티리얼·트랜스폼을 USD Prim/Attribute로 변환 (pxr.Usd, UsdGeom)
  • StageWriter — 변환 결과를 .usd/.usda Stage 파일로 저장/게시

변환된 에셋은 별도 가공 없이 Omniverse Kit 앱과 웹 스트리밍 뷰어에서 바로 로드해 확인할 수 있었습니다.

Omniverse 확장 프로그램(Extension) 개발 및 환경 구축

개발 의도. 웹 클라이언트가 보내는 커스텀 스트리밍 메시지를 Kit 앱 내부에서 실제로 처리할 로직이 필요했습니다. Kit 앱에 탑재되는 자체 Extension을 개발하고, 정상 동작하는 실행 환경을 구축했습니다.

  • omni.ext 프레임워크 위에 커스텀 Extension 구현 — 웹 클라이언트의 event_type/payload 메시지 수신
  • StreamMessageExtension → MessageDispatcher → SceneLoadHandler / SelectionSyncHandler 구조로 라우팅 후 Kit 앱 API(Stage 열기, Selection 변경) 호출
  • 처리 결과를 ~Result / ~Confirmation 메시지로 웹 클라이언트에 응답, Extension 매니페스트 및 로컬 개발 환경 구축

데이터 중심(Data-Driven) 인벤토리 시스템 설계 및 구현

개발 의도. 기획자가 CSV 파일 수정만으로 프로그램 내 아이템 데이터를 실시간으로 수정할 수 있는, 확장성 높고 독립적인 인벤토리 아키텍처를 구축했습니다.

Data Flow
flowchart LR
  A[CSV 파일] --> B[CSV Parser]
  B --> C[Data Manager]
  C --> D[인벤토리 시스템]
  D --> E[Unity UI]
  D --> F["3D 프리팹 동적 시각화"]
  • Model — CSVParser / CSVManager / CSVReader / Data Struct: 고유 ID를 Key로 Dictionary 캐싱
  • Controller — InventoryItem(슬롯 아이템 객체) / InventoryController(상태·데이터 흐름 총괄)
  • View — 타 개발자의 비동기 스크롤 UI 컴포넌트에 MVC 기반 데이터 바인딩 로직을 결합 (스크롤 UI 구조는 수정 불가 조건)
신규 데이터 클래스 정의만으로 자동 바인딩되는 확장성을 확보해, 인벤토리 UI를 완전히 갈아엎어도 코드 수정 없이 대응 가능한 독립적 컴포넌트 구조를 만들었습니다.
2

확장성을 고려한 CSV 데이터 로드 파이프라인 구축

개발 의도. 기획 데이터를 코드와 완전히 격리해 개발자 개입 없이 기획자가 독립적으로 콘텐츠를 추가·제어할 수 있는 공용 파이프라인을 만들었습니다. 협업 효율을 위해 저수준 파일 처리와 고수준 파싱/캐싱 레이어를 나눠 공동 개발했습니다.

  • FileStreamReader — 로컬 디스크 CSV를 안전하게 읽는 저수준 I/O 클래스
  • CSVParserBase<T> — 제네릭 구조로 다양한 데이터 클래스에 자동 매핑하는 공용 파서
  • MasterDataManager — 유일성이 보장된 Dictionary로 메모리 상주, 다른 시스템의 안전한 접근을 중재
인터페이스 규격을 먼저 정의하고 개발해, 파일 읽기 방식이 바뀌어도 파서 엔진과 인벤토리 시스템은 사이드 이펙트 없이 독립 동작합니다. 기획자의 오타·타입 실수로 인한 런타임 크래시를 막기 위해 예외 처리를 결합하고, 로그 시스템과 연계해 오류가 발생한 정확한 라인(Line)을 추적할 수 있게 했습니다.
3

사용자 환경 설정(Preference) 관리 시스템 및 UI

개발 의도. 사용자가 변경한 환경 설정을 유지·관리하기 위해 섹션별 관리가 쉽고 직관적인 편집이 가능한 .ini 포맷을 선택했습니다. 싱글톤 사용을 의도적으로 지양해 결합도를 낮췄습니다.

  • .ini 파서 → 데이터 저장 클래스 → 접근/제어 중재 클래스 → Controller → Viewer의 5단계 레이어 파이프라인
  • 런타임에는 인메모리 값만 변경하고, 옵션 창을 닫거나 저장 버튼을 누를 때만 파일 작성 — 배치 쓰기로 디스크 I/O 최적화
  • Controller의 데이터 상태 변경을 Viewer가 감지해 자동 동기화하는 Observer 구조로 UI와 로직을 완전히 분리

JSON 기반 데이터 직렬화/역직렬화 시스템 구축

개발 의도. Unity 기본 타입(Vector3, Quaternion, Color 등)은 JSON으로 기본 직렬화가 되지 않고, VR 콘텐츠 저작 도구 특성상 Transform·머티리얼 색상·텍스트 폰트/내용 등 다양한 커스텀 속성을 안정적으로 저장·복원해야 했습니다. 팀원이 구축해둔 시스템을 이어받아 안정성을 높이는 방향으로 개선했습니다.

직렬화 흐름
flowchart LR
  Obj["오브젝트 속성"] --> DC["TransformData / MaterialColorData / TextData"]
  DC --> Enc["Encoder (Singleton)"]
  Enc --> JSON[("JSON 파일")]
  JSON --> Dec["Decoder (Singleton)"]
  Dec --> DC2["데이터 클래스 복원"]
  DC2 --> Obj2["오브젝트 재적용"]

속성별로 직렬화 대상 데이터 클래스를 분리 설계해, 새로운 속성 타입을 추가하기 쉬워지고 저장/불러오기 과정의 안정성을 확보했습니다.

VR 콘텐츠 제작 효율화 툴 개발

개발 의도. 코드를 직접 작성하지 않고도 기획자 등 비개발 인력이 VR 콘텐츠의 오브젝트 배치, 씬 구성, 인터랙션 설정까지 할 수 있도록 해 제작 공정 전체의 효율을 높이고자 했습니다.

  • Unity 에디터 확장 + 런타임 UI를 모두 지원 — 오브젝트 배치/구성 기능과 인터랙션 기능을 직접 담당
  • 어떤 트리거(클릭, 충돌 등)에 어떤 액션(이동, 사운드 재생 등)이 실행될지 GUI에서 정의
  • 설정은 InteractionData로 저장, 런타임에 InteractionRuntime이 읽어 실제 동작으로 실행
개발 지식이 없는 기획자도 직접 VR 콘텐츠를 제작·수정할 수 있게 되어 제작 공정이 효율화됐습니다.

확률 기반 랜덤 박스 시스템

개발 의도. 역전의 발판 혹은 승리를 굳힐 기회를 주어 플레이를 다채롭게 하기 위한 아이템 시스템입니다. 각 아이템의 등장 확률은 등장 빈도 값에 따라 무작위로 결정됩니다.

아이템 등장 빈도는 기본값 10인 정수 데이터이며 0 미만이 될 수 없습니다.
아이템 등장 확률 = 해당 아이템의 등장 빈도 / 모든 아이템의 등장 빈도 합

  • RandomGenerator<T> — 무작위 리스트를 만들어 오브젝트를 뽑아주는 제네릭 클래스
  • Item / ItemBox — 아이템을 생성/저장/제거하는 클래스, ExorcistItemBox / DollItemBox가 진영별로 상속
RandomGenerator.csC#
public class RandomGenerator<T>
{
    List<T> randomlist = new List<T>();

    public void Add(in T item)
    {
        randomlist.Add(item);
    }

    public void Add(in T item, int count)
    {
        for (var i = 0; i < count; ++i)
        {
            randomlist.Add(item);
        }
    }

    public void AddRange(in List<T> items)
    {
        randomlist.AddRange(items);
    }

    public T GetItem()
    {
        int i = Random.Range(0, randomlist.Count);
        return randomlist[i];
    }

    public T GetAndRemoveItem()
    {
        int i = Random.Range(0, randomlist.Count);
        T item = randomlist[i];
        randomlist.RemoveAt(i);
        return item;
    }
}
예를 들어 100개의 아이템에서 25%의 확률로 하나의 아이템을 획득하게 하려면, 25개의 동일 아이템을 리스트에 넣어 확률을 만듭니다 — Add(item, count)가 이 역할을 담당합니다.

  • 상호작용이 없는 UI는 Raycast Target을 비활성화해 불필요한 히트테스트 제거

개발 의도. 대부분의 상호작용이 캐스팅(게이지 충전) 후 작동하기 때문에 개발했습니다.

무한 배경을 위한 스크롤링 시스템

개발 의도. 배경 이미지가 끊기지 않고 적은 양의 이미지만으로 무한히 이어지는 것처럼 보이도록 개발했습니다.

  • 동일한 이미지 2장을 나란히 배치하고, 이미지의 가로 길이만큼 이동하면 위치를 원점으로 되돌리는 방식
Background.hC++
class BackGround
{
public:
    BackGround()
        : x(0), y(0),
          hBackImage((HBITMAP)LoadImage(NULL, BackgroundImagePath,
              IMAGE_BITMAP, 0, 0, LR_LOADFROMFILE | LR_CREATEDIBSECTION))
    {
        GetObject(hBackImage, sizeof(BITMAP), &bitBack);
        bx = bitBack.bmWidth;
        by = bitBack.bmHeight;
    }

    void Update(float dt)
    {
        x -= 1;
        if (x == -bx)
        {
            x = 0;
        }
    }

    void Draw(HDC hdc)
    {
        HDC hMemDC;
        HBITMAP hOldBitmap;
        CreateCompatibleDCAndSelectBitmap(hdc, hBackImage, hMemDC, hOldBitmap);
        BitBlt(hdc, x,      y, bx, by, hMemDC, 0, 0, SRCCOPY);
        BitBlt(hdc, x + bx, y, bx, by, hMemDC, 0, 0, SRCCOPY);
        DeleteCompatibleDC(hMemDC, hOldBitmap);
    }

private:
    int x, y;
    HBITMAP hBackImage;
    BITMAP bitBack;
    int bx, by;
};
두 이미지를 x, x + bx 위치에 각각 그리기 때문에 한 이미지가 화면 밖으로 완전히 빠져나가기 전에 다음 이미지가 이어져 끊김 없는 배경이 완성됩니다.
